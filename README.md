# Dialog G2 Panel

Чистый старт проекта шкафа аварийного освещения Dialog G2.

## Состав

- `dialog-g2-engine` - постоянный процесс управления шкафом.
- `dialog-g2-hmi` - HMI как потребитель состояния и источник команд оператора.
- `ModbusController` - релейная шина WaveShare.
- `MeteringBusController` - измерительная шина: Modbus RTU приборы и BMS JBD.

На измерительной шине ADL200 использует Modbus-адрес `6`. Адрес `1` зарезервирован из-за конфликта с оборудованием BMS и не должен назначаться ни одному Modbus-устройству.

## Сборка

```powershell
cmake --preset msvc-debug
cmake --build --preset debug
```

## Движок

`dialog-g2-engine` запускается как постоянный процесс. Он опрашивает релейную и измерительную шины, пересчитывает состояние шкафа и циклически записывает JSON-снимок.

```powershell
$env:PATH="C:\Qt\6.10.3\msvc2022_64\bin;$env:PATH"
.\build-msvc\Debug\dialog-g2-engine.exe .\state\current_state.json
```

Для подробного лога:

```powershell
.\build-msvc\Debug\dialog-g2-engine.exe .\state\current_state.json --log-debug
```

Demo-режим для настройки HMI без реального шкафа:

```powershell
.\build-msvc\Debug\dialog-g2-engine.exe .\state\current_state.json --demo
```

В `--demo` engine не открывает RS485-порты, но продолжает работать вечным циклом и пишет правдоподобный `state.json`: нормальное напряжение, исправная АКБ, мощности линий по номиналу, утечки `0`.

Приоритет режима:

1. `Пожар` - внешний пожарный вход или ручная авария.
2. `Авария` - контакт реле контроля напряжения.
3. `Тест ручной` - ручной тест.
4. `Тест по расписанию` - плановый тест.
5. `Норма` - штатная работа.

## Релейные выходы WaveShare

Выходы линий подключены через нормально-замкнутые контакты. Внутри программы
`LineOutputState::On` означает, что линия должна быть включена, но физически на
соответствующий coil WaveShare записывается `0`: реле обесточено, контакт замкнут.
`LineOutputState::Off` означает отключение линии, физически coil записывается в `1`.

Служебные реле шкафа управляются отдельно. Лампа неисправности тоже выполнена через
нормально-замкнутый контакт: в норме coil удерживается включенным, при аварии
обесточивается. Лампа теста управляется прямо: при активном тесте coil включается.

### Отсутствие данных на панели

Без связи с engine показания очищаются: вместо измерений — прочерки, вместо исправности — «Нет данных».
При таймауте или ошибке опроса измерителя его предыдущие показания сбрасываются до следующего успешного ответа.
Реальный измеренный ноль сохраняется как ноль. Пустое измерение передается как JSON `null`.
Сводные статусы системы и линий требуют наличия соответствующих измерений; ответ одного прибора не подтверждает исправность остальных.
При явном запуске с `--demo` панель показывает предупреждение «ДЕМОРЕЖИМ»; для реального шкафа этот аргумент не нужен.

Проверки: собрать цели `telemetry-tests` и `test-controller-tests`, запустить их из `build-msvc/Debug`.
