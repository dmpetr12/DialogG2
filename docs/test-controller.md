# TestController

`TestController` управляет ручными и плановыми тестами шкафа. Он не читает Modbus напрямую: на вход получает текущее состояние линий с измеренной мощностью, запросы тестов и приоритетные входы, а на выход отдаёт активный тест, журнал и обновлённые результаты линий.

## Типы тестов

Тест исправности:

```text
включить общее реле режима Тест / Пожар / Авария
ждать прогрев functionalWarmupSeconds, по умолчанию 120 секунд
измерить мощность линий
сравнить с nominalPower по powerTestTolerancePercent
```

Тест длительности:

```text
включить общее реле режима Тест / Пожар / Авария
держать durationSeconds, заданный из HMI или расписания
после завершения измерить мощность
сравнить с nominalPower по расширенному допуску
```

Расширенный допуск сейчас считается как:

```text
line.powerTestTolerancePercent * durationToleranceMultiplier
```

По умолчанию множитель равен `2.0`: при базовом допуске линии `5%` тест длительности проверяется по `10%`.

Постоянный контроль мощности в рабочем режиме делает не `TestController`, а `LineOperationalMonitor`.
Он ждёт прогрев после включения линии и только потом формирует текущую неисправность линии.

## Приоритеты

От высшего к низшему:

```text
1. Пропало напряжение
2. Пожар
3. Ручной тест длительности
4. Ручной тест исправности
5. Тест длительности по расписанию
6. Тест исправности по расписанию
7. Норма
```

Если активный тест вытесняется более высоким режимом, он сразу завершается записью в журнал:

```text
status = interrupted_by_priority
statusText = Прерван по приоритету
```

Тест после такого прерывания не возобновляется автоматически.

## Остановка оператором

Активный тест можно остановить отдельной командой:

```text
TestControllerInputs.stopRequested = true
```

В реальном цикле сюда подаются команда HMI "стоп теста" и активный вход 3 первого WaveShare (`manualStopButtonActive`).
Такой тест сразу завершается и попадает в журнал:

```text
status = stopped_by_operator
statusText = Остановлен оператором
```

Измерения линий при такой остановке не записываются, потому что тест не дошёл до своей контрольной точки.

## Хранение

Эксплуатационный журнал тестов хранится отдельно от технического лога:

```text
state/test_journal.json
```

Формат:

```text
schemaVersion
entries[]
```

Каждая запись содержит тип теста, источник, время начала/окончания, общий итог и измерения по линиям.

Последний результат теста по каждой линии хранится в конфигурации линий:

```text
config/lines.json
lines[].lastFunctionalTest
lines[].lastDurationTest
```

Это сделано специально: карточка линии в HMI сможет показать последние результаты без чтения полного журнала.
При завершении теста `LineManager::applyTestResults()` обновляет эти поля, после чего `LineManager::saveConfig()` сохраняет их.

## Расписание

Расписание хранится в формате предыдущей панели:

```text
config/test_schedule.json
```

Файл является JSON-массивом записей:

```json
[
  {
    "enabled": true,
    "period": "ежедневно",
    "startDate": "2026-08-09",
    "startTime": "10:00",
    "testType": "Функциональный тест",
    "weekDays": []
  }
]
```

Поддерживаемые `period`:

```text
один раз
ежедневно
дни недели
раз в месяц
раз в 3 месяца
раз в полгода
раз в год
```

Для `дни недели` используются ключи старой панели:

```text
Mon Tue Wed Thu Fri Sat Sun
```

`testType`:

```text
Функциональный тест
Тест на время
```

Также принимаются служебные английские значения `functional`, `functional_test`, `duration`, `duration_test`.

`TestScheduleManager` проверяет расписание в вечном цикле `engine`. Если плановое время уже наступило, но прошло не больше 90 секунд, он выдаёт запрос в `TestController`. Один и тот же planned-момент не запускается дважды.

## Связь с LineManager

В постоянном цикле `engine` результат `TestController` подаётся в общую логику состояния, а затем `LineManager` получает итоговые флаги реле:

```text
snapshot.mode != Normal      -> LineManagerInputs.modeRelayOn
snapshot.health == Fault     -> LineManagerInputs.faultLampOn
snapshot.activeTest.active   -> LineManagerInputs.testLampOn
```

`LineManager` после этого сформирует полный байт реле WaveShare. Линии во время теста не включаются принудительно: переключение на резервное питание происходит аппаратно после включения общего реле режима.
