# Файл состояния

Движок формирует JSON-снимок состояния шкафа. HMI должна читать готовое состояние и не вычислять режимы сама.

Основной файл для разработки:

```text
state/current_state.json
```

Ключевые поля:

- `schemaVersion` - версия формата.
- `timestamp` - время формирования снимка в UTC.
- `mode`, `modeCode`, `modeText` - режим шкафа.
- `health`, `healthCode`, `healthText` - исправность шкафа.
- `explanation` - короткая расшифровка для главного экрана.
- `voltageControlOk` - контакт реле контроля напряжения в норме.
- `fireInputActive` - внешний пожарный вход.
- `manualEmergencyActive` - ручная авария, отображается как `Пожар`.
- `testActive`, `testKind`, `testKindCode`, `testKindText` - состояние и тип теста.
- `testSource`, `testSourceCode`, `testSourceText` - источник теста: ручной или по расписанию.
- `activeTest` - параметры текущего теста: старт, расчётное завершение, прогрев или длительность.
- `inputVoltage` - входное напряжение, В.
- `inputCurrent` - входной ток, А.
- `inputPower` - входная активная мощность, Вт.
- `inputFrequency` - частота входа, Гц.
- `battery` - агрегированное состояние АКБ.
- `lines` - массив линий.
- `testJournal` - записи завершённых или прерванных тестов.
- `activeFaults` - список активных внутренних неисправностей.

Неизвестные измерения пишем как `null`. HMI отображает такие значения прочерком.
Не подставляем условные `220 В`, `50 Вт`, `24 °C`, пока прибор реально не дал значение.

Числовые режимы:

```text
0 = Норма
1 = Авария
2 = Пожар
3 = Тест ручной
4 = Тест по расписанию
```

Числовая исправность:

```text
0 = Норма
1 = Неисправность
```

## АКБ

На главный экран выводим только:

- `battery.stateText` - `Норма`, `Предупреждение`, `Неисправность`, `Нет связи`.
- `battery.socPercent` - ёмкость/заряд в процентах. Если `null`, показываем прочерк.

Остальные поля нужны для отдельного экрана АКБ:

- `connected` - физически/логически есть связь с BMS.
- `communicationOk` - последние опросы успешны.
- `voltage` - напряжение батареи, В.
- `current` - ток батареи, А.
- `remainingCapacityAh` - остаточная ёмкость, Ач.
- `nominalCapacityAh` - номинальная ёмкость, Ач.
- `fullChargeCapacityAh` - полная доступная ёмкость, Ач.
- `cycleCount` - количество циклов.
- `cellCount` - количество ячеек.
- `cellVoltages` - напряжения ячеек, В.
- `minCellVoltage`, `maxCellVoltage`, `cellVoltageDelta` - минимум, максимум и разброс ячеек, В.
- `temperatures` - температуры датчиков, °C.
- `minTemperature`, `maxTemperature` - минимум и максимум температур, °C.
- `chargeAllowed` - заряд разрешён BMS.
- `dischargeAllowed` - разряд разрешён BMS.
- `balancingActive` - идёт балансировка.
- `heatingActive` - включён подогрев.
- `protectionStatusRaw` - сырые биты защит BMS.
- `alarmStatusRaw` - сырые биты предупреждений BMS.
- `faults` - список эксплуатационных неисправностей.
- `warnings` - список эксплуатационных предупреждений.

Состояние АКБ:

```text
0 = Норма
1 = Предупреждение
2 = Неисправность
3 = Нет связи
```

## Линии

У линии отдельно храним:

- `enabled` - линия используется в конфигурации.
- `name` - название линии для HMI, журналов и настроек.
- `kind` / `kindText` - тип линии: постоянная или непостоянная.
- `requestInputActive` - для непостоянной линии активен внешний вход включения.
- `outputState` / `outputStateText` - текущее командное состояние выхода: включена или выключена.
- `state` / `stateText` - исправность линии.
- `nominalPower` - номинальная, установочная мощность линии, Вт.
- `powerTestTolerancePercent` - допустимое отклонение измеренной мощности при тесте, %.
- `leakageCurrentLimit` - допустимый ток утечки, мА. По умолчанию `30`.
- `leakageCurrent` - измеренный ток утечки, мА; пока измерения нет, `null`.
- `operationalCheck` - текущий оперативный контроль мощности в рабочем режиме.
- `lastFunctionalTest` - время, измеренная мощность и результат последнего теста исправности.
- `lastDurationTest` - время, измеренная мощность и результат последнего теста длительности.

Тип линии:

```text
0 = Постоянная
1 = Непостоянная
```

Состояние выхода:

```text
0 = Выключена
1 = Включена
```

Состояние линии:

```text
0 = Норма
1 = Неисправность
2 = Отключена
3 = Пробой изоляции
```

Оперативный контроль линии:

```text
0 = Не контролируется
1 = Прогрев
2 = Норма
3 = Неисправность
4 = Нет измерения
```

Постоянные линии и включённые непостоянные линии проверяются по текущей мощности после прогрева.
Выключенные непостоянные линии получают `Не контролируется` и не формируют неисправность.
Во время прогрева линия не формирует неисправность. После прогрева `Нет измерения` или мощность вне допуска переводят линию в `LineState::Fault`, а общее состояние шкафа становится `Неисправность`.

## Тесты

Тип теста:

```text
0 = Нет
1 = Исправность
2 = Длительность работы
```

Источник теста:

```text
0 = Нет
1 = Ручной
2 = По расписанию
```

Результат теста:

```text
0 = Нет
1 = Выполняется
2 = Исправно
3 = Неисправно
4 = Прерван по приоритету
5 = Остановлен оператором
```

`testJournal[]` в текущем снимке содержит записи из сохраняемого журнала:

```text
state/test_journal.json
```

Каждая запись хранит:

- `kind` / `kindText` - тип теста.
- `source` / `sourceText` - ручной или по расписанию.
- `startedAt`, `finishedAt` - начало и завершение.
- `status` / `statusText` - общий итог.
- `reason` - причина прерывания или дополнительное пояснение.
- `lines[]` - измеренная мощность, номинал, допуск и итог по каждой линии.

Тест исправности после прогрева использует обычный допуск линии `powerTestTolerancePercent`.
Тест длительности использует расширенный допуск: базовый допуск линии умножается на коэффициент контроллера.

Последние результаты тестов линии дополнительно сохраняются в:

```text
config/lines.json
```

Поля `lines[].lastFunctionalTest` и `lines[].lastDurationTest` нужны для быстрого отображения карточки линии и сохраняются между перезапусками.
